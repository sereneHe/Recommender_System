# 从「证伪树」到「漏斗式最优解搜索」

## 一、现有 Evidence 节点分别是什么

| 节点 | 它问的问题 | 类型 | 当前状态 | 作用 |
|---|---|---|---|---|
| **C0a** 产品命题 | 冻结的 HC-CE 是否稳定优于 Mark-CC？ | 主张(claim) | contradicted | 回答"最终方法值不值得采用" |
| **C0b** 机制命题 | CE-only 相对同一 NN 的无约束是否有增量？ | 主张(claim) | contradicted | 回答"提升是否来自 CE 本身" |
| **D0** 比较合同 | 两臂是否在相同 split / 信息集 / 预处理下比较？ | 门(gate) | partial | 所有主结论的公平性前置门 |
| **D0.2** fold-W cache | 需要 W 的臂是否复用同一图缓存？ | 门(gate) | ✗ 未实现 | CE/W 归因的硬门 |
| **B0** 横向基线轨 | 各数据族可横向调用的基线是否齐全？ | 轨(rail) | partial | 提供"参照系" |
| **B0.mark_cc_100** | Mark-CC-100 参照是否存在？ | 基线 | ✗ 缺 | 公平比较的外部约束参照 |
| **P1.2** CE vs NN | 同 NN 下 CE 是否有增量？ | 实验 | contradicted | 机制核心 |
| **P1.3** 非线性边界 | 非线性/非高斯下统计量是否失效？ | 实验 | contradicted | 划定 CE 的适用边界 |
| **P1.4** W 消融 | W 约束本身是否有影响？ | 实验 | equivalent | 排除 W 的干扰 |
| **P2** FRED 开发 | 真实数据上调参/消融/稳健性 | 阶段 | n/a | 真实域验证 |
| **P6** CoDiet | 离散/组成型数据的 type-aware CMI 路线 | 阶段 | n/a | 扩展域 |
| **P8** BD | 单点图不稳定时的后验稳定约束 | 阶段 | n/a | 扩展路线 |
| **F0** 最终冻结评估 | 参数冻结后是否有未调参的 locked holdout？ | 门(gate) | ✗ 未实现 | 最终主张的硬门 |

> **它们合起来是一棵"证伪树"**：每个节点是一个"X 是否有用"的假设，整体近似取**合取**。
> 问题：**如果全部被否定，你手上就没有任何可交付的方法**——这正是你担心的情形。

---

## 二、新设计目标

> 先划一个**保证有解的大范围**，再**单调缩小**，最后得到**最小范围内的最优解**；
> 无论中间否定多少假设，**一定有一个可交付的方法**。

核心思路：**把"存在性"与"最优性"分开。**

1. **存在性**由"锚点"保证：把最好的已知基线放进搜索空间，最优解必然 ≥ 锚点。
2. **最优性**由"逐级缩小"保证：每一步都保留当前最优，性能单调不降。

---

## 三、漏斗式设计（Coarse-to-Fine with Guarantee）

```
Stage 0  定义设计空间 S + 锚点 a*        ← 保证"有解"（a* ∈ S）
   │
Stage 1  粗筛：全组合 × 最小预算          ← 淘汰被支配区域，保留 top 50%
   │      (successive halving)
Stage 2  精筛：top 候选 × 更多 seed/预算   ← 保留 top 25% → top k
   │
Stage 3  确认：top 1–3 vs 锚点 + 基线      ← paired cluster bootstrap，预注册门槛
   │      命中 → 交付该候选
   │      未命中 → 交付锚点（兜底），并报告边界
Stage 4  冻结 + locked holdout            ← 最终主张
```

**关键性质**：`best(S)` 随范围缩小**单调不降**；锚点始终在 S 内 → **永不空手**。

## 四、设计空间 S（本项目的轴）

| 轴 | 取值 | 说明 |
|---|---|---|
| F1 learner | NN(hc_predictor) / XGB(mark) | 网络 vs 树 |
| F2 graph source | true DAG(oracle) / estimated DAG / BD posterior | 图来源 |
| F3 constraint | none / W / CE / W+CE | 约束类型 |
| F4 CE statistic | linear residual-cov / quantile / discrete-CMI / nonlinear partial-corr | 统计量 |
| F5 domain | ER / SF / FRED / CoDiet | 数据域 |
| F6 hyperparams | lr, wd, hidden, depth, budget | 训练配置 |

**锚点 a\*** = 在 F1×F2 上取 {`mark_100`, `mark_cc_100`, `hc_predictor-no-constraint`} 中最优者。
（`mark_cc_100` 目前缺失 → 先补齐，否则锚点用 `mark_100`。）

**主指标**：fold-normalized macro-NMSE；相对改善 `rel = (anchor - cand)/anchor`。

## 五、四条保证机制

| 机制 | 规则 |
|---|---|
| **锚点包含** | a* 永远在 S 内 → 最优解存在 |
| **单调保留** | 每级至少保留当前最优（含锚点），性能不降 |
| **支配才淘汰** | 只有"在当前预算下被统计支配"的区域才剔除（避免噪声误杀） |
| **兜底交付** | 若 top-1 未显著超过锚点 → 交付锚点，结论改为"划定边界"，仍有产出 |

## 六、旧节点如何映射进漏斗

| 旧节点 | 在新漏斗中的角色 |
|---|---|
| B0 基线轨 | **Stage 0 锚点** |
| D0 比较合同 | 贯穿所有 Stage 的公平性约束 |

## 七、预算与停止规则

- **Successive halving**：第 k 级预算 ≈ 上一级 × 2–3，候选数 ≈ ÷2。
- **停止条件（满足其一）**：
  1. top-1 相对锚点 `CI_lo > 0` 且 `rel ≥ 预注册门槛`（如 5%）→ 交付 top-1；
  2. 预算耗尽 → 交付当前最优（可能是锚点）；
  3. 剩余候选在统计上不可区分 → 取实现最简单者（奥卡姆）。
- **预注册**：S、锚点、主指标、门槛、每级预算，全部在跑之前写死。

---

## 八、交付物

1. **一个可交付的方法**：`best(S)`（或锚点兜底），永远存在。
2. **范围–性能曲线**：证明"缩小范围"确实提升性能（漏斗有效性）。
3. **边界报告**：哪些区域被支配、哪些统计量在什么条件下失效。
4. **仪表盘**：漏斗每级的候选数、保留数、当前最优、相对锚点 CI。

> 这样即使 CE 主线被否定，你仍交付"锚点 + 边界 + 漏斗"三件产出，而不是零。
